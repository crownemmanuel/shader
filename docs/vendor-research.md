## Primary sources

- [Sony Camera Remote SDK](https://support.d-imaging.sony.co.jp/app/sdk/en/index.html): ILCE-7M4 is supported. SDK 1.12 added wireless LAN support for specified cameras including ILCE-7M4; firmware and per-device API references remain decisive. Current SDK page lists version 2.02.00. Picture-profile support is not a guarantee that every in-camera color feature is writable in every mode.
- [Sony SDK download and agreement](https://support.d-imaging.sony.co.jp/app/sdk/licenseagreement_d/en-US.html): the native distribution includes the API reference and sample app. Do not substitute the legacy ScalarWebAPI for a7 IV SDK control. The user's second Sony camcorder must be identified before choosing an API.
- [Blackmagic ATEM developer page](https://www.blackmagicdesign.com/developer/products/atem): ATEM SDK exposes embedded camera control. This implementation currently uses the open-source `atem-connection` network implementation, not the proprietary Switcher SDK.
- [Blackmagic Camera Control, August 2025](https://documents.blackmagicdesign.com/DeveloperManuals/BlackmagicCameraControl.pdf): REST API, color correction endpoints, SDI control and native parameter addressing. Compatible REST cameras require Web Media Manager enabled. Camera-hosted REST documentation is at `/control/documentation.html`; the API prefix is `/control/api/v1/`.
- [PTZOptics HTTP getting started](https://docs.ptzoptics.com/dev/guides/http-api-getting-started/): exact CGI ordering and HTTP methods matter; Digest authentication is used when enabled.
- [PTZOptics red gain](https://docs.ptzoptics.com/dev/http-api/color/red-gain-get-red-gain/): newer supported models use `post_image_value&rgain&value`, with manual white balance required.
- [PTZOptics device query](https://docs.ptzoptics.com/dev/http-api/query/get-device-config/) and [image configuration](https://docs.ptzoptics.com/dev/http-api/query/get-image-config/): model-specific query support. Do not infer that legacy cameras implement these endpoints.
- [PTZOptics VISCA exposure](https://devs.ptzoptics.com/visca-api/exposure/), [movement](https://devs.ptzoptics.com/visca-api/movement/) and [inquiries](https://docs.ptzoptics.com/dev/visca-api/inquiries/): packet formats and native ranges. Some vendor table entries appear inconsistent (e.g. shutter/iris); those were deliberately not promoted into typed controls.
- [MCP transport specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports): stdio framing and transport requirements. Shader uses the official MCP TypeScript SDK.
- [Groq tool use](https://console.groq.com/docs/tool-use/overview), [Claude tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview), [OpenAI vision](https://developers.openai.com/api/docs/guides/images-vision): provider/tool and image wiring.

Discovery cannot identify every camera across routed VLANs or networks that block multicast. DNS-SD, SSDP and WS-Discovery candidates are hints; protocol handshakes verify supported connections. Saved targets and manual addresses cover devices that do not advertise. Do not use input names as proof of physical camera model.

The user authorized Sony license acceptance and installation. Runtime initialization and enumeration now pass on macOS with the official library layout; no Sony camera was visible on this network. Names are generated from installed headers, while supported control availability is obtained from the connected device. See `native/sony/README.md` for the exact boundary.

See [volunteer-controls.md](volunteer-controls.md) for deterministic shading semantics, operating limits, ATEM tally mapping and shared capture behavior.
